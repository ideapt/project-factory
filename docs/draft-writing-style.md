# 자동 생성 기획서의 문장 기준

적용일: 2026-10-27 · 기존 v0.7 작성본 구조 유지

## 적용 범위

humanizer 스킬의 한국어 윤문 기준을 참고해 생성기가 직접 쓰는 설명·개요·실행 제안 문구를 고쳤습니다. 이후 미리보기와 Markdown 내려받기에 같은 문구가 적용됩니다. 외부 AI나 별도의 탐지기를 실행하지 않습니다.

입력 답변과 자료를 일괄 치환하지 않습니다. 사용자 답변·원자료 발췌·직접 인용·수치·날짜·고유명사·출처·파일 위치·해시·OCR 점수·미확인 상태는 보존합니다. 특히 문장 다듬기를 이유로 가정·제안을 사실이나 검증 결과로 바꾸지 않습니다.

## 문장 규칙

1. 명사를 길게 나열하기보다 누가 무엇을 할지 동사로 씁니다.
2. ‘구조화하다’, ‘자동 수행하다’처럼 딱딱한 표현은 의미를 유지하면서 쉬운 말로 바꿉니다.
3. 긴 설명은 읽는 순서에 맞춰 나누되 단어마다 쉼표를 넣지 않습니다.
4. 사업 문서에 맞는 존댓말을 유지합니다. 문장을 부드럽게 하려고 구어체·과장·확신을 덧붙이지 않습니다.
5. 자료 내용과 작성자의 판단을 구분합니다. 원문을 그대로 넣는 부분을 자동 요약했다고 표시하지 않습니다.
6. 상태 문구와 보호 데이터는 윤문 대상에서 제외합니다. ‘미확인’은 문체 점검보다 우선합니다.

## 수정 예

| 이전 생성 문구 | 수정한 문구 |
|---|---|
| 이 초안은 입력한 내용과 자료를 구조화했습니다. | 입력한 내용과 자료를 정리한 초안입니다. |
| 원문 사실 확인·수치 계산·법적 판단을 자동 수행하지 않습니다. | 원문 확인, 계산 검증, 법적 판단은 별도로 해야 합니다. |
| 사용자 입력 자료 요약: | 입력한 자료 내용: |
| 입력한 근거를 같은 기간·단위로 비교하고 반대 근거·자원 중복을 확인합니다. | 근거 자료의 기간과 단위를 맞춰 비교합니다. 반대 근거가 있는지, 같은 자원을 중복 계산하지 않았는지도 확인합니다. |

전체 [수정 전 예시](../examples/draft-style-before.md)와 [수정 후 예시](../examples/draft-style-after.md)는 같은 가상 입력으로 생성했습니다. 실제 사업 근거는 아닙니다.

## 의미 보존과 검사

수치·날짜·고유명사, 인과관계 방향, 부정 표현, 직접 인용, 주장·결론, 격식 수준의 6항을 검토했습니다. 자동 검사는 예시 전후 수치와 미확인 상태를 비교하고, 입력문·인용·출처·해시·위치·OCR 점수를 그대로 출력하는지 확인합니다. 인과·어조는 예시와 생성 문구를 별도로 대조했습니다.

`node scripts/check-draft-style.cjs`로 회귀 검사를 실행합니다. 같은 입력으로 생성되는 미리보기와 내려받기 모두 `PlanningDraft.generate`를 사용하므로 별도 윤문 단계 없이 적용됩니다.

이 검토는 편집상 판단입니다. AI 작성 여부를 판별하거나 자연스러움을 객관적으로 점수화한 결과로 해석하지 않습니다.
