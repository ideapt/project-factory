# 프로젝트 공장 통합 기획 체계 v0.3

이 문서는 v0.3 설계 기록입니다. 현재의 직무·사업장·목적별 구조와 63개 기획은 [v0.4 개편 안내](planning-v04.md)를 우선합니다.

## 목적

수익형 신규 사업뿐 아니라 내부 개선·경영·재무·시설·숙박 운영까지 한 체계에서 기획합니다. 사용자는 조직도처럼 분야를 펼쳐 개별 기획을 선택하거나 여러 기획을 묶습니다. FM은 시설관리(Facility Management)로 해석한 초안이며 추후 명칭을 바꿀 수 있습니다.

이번 결과는 **로컬에서 실행하는 기능 시안과 확장 설계**입니다. 호스팅 게시·계정·다중 사용자 승인·실시간 데이터 수집·AI 본문 생성은 연결하지 않았습니다. 작성 내용으로 구조화한 기획서를 내보내는 기능을 제공합니다.

## 분류 원칙

사이트는 산출물, 경진대회는 제출 목적, 호텔은 산업, 재무는 업무 기능으로 서로 다른 축입니다. 화면에서는 찾기 쉬운 9개 진입 분야로 보여주되 내부적으로 고유 기획 번호와 분야 태그로 구분합니다. 호텔 사업 + 재무 + FM처럼 여러 분야를 동시에 선택할 수 있습니다. 하나의 조직에 소속되어야 하는 실제 조직도가 아닌 **기획 선택용 분류도**입니다.

## 화면과 사용 순서

1. 왼쪽 분류도에서 분야를 펼치거나 전체 검색합니다.
2. 기획을 클릭하면 목적·질문·데이터·지표·검증 조건을 확인합니다.
3. 개별 기획을 선택 목록에 추가합니다. 여러 개면 통합기획 모드가 됩니다.
4. 공통 작성 영역에서 제목·대상·기간·예산·담당·성과 목표를 한 번 적습니다.
5. 선택한 기획별 질문에 답하고 출처·상태를 붙입니다.
6. 충돌 검토 영역에서 예산·기간·인원·가정·권한의 일치 여부를 확인합니다.
7. Markdown 기획서와 복원용 JSON을 내려받습니다.

## 공통 기반과 조합

모든 기획은 배경·현황·목표·관계자·대안·실행·자원·재무·근거·검증·위험·판정의 공통 뼈대를 사용합니다. 내부 기획에서는 고객을 이용자·업무 수혜자·승인자로 바꿔 해석하며 구매검증을 시범 적용·업무 성과·승인 조건 검증으로 바꿉니다. 직접 매출이 없는 경우 수익 대신 비용·시간·품질·위험 감소를 측정하고 금액 환산 근거와 미환산 효과를 구분합니다.

통합기획은 공통 항목을 한 번만 기록하고 유형별 질문을 추가합니다. 같은 기획 번호를 여러 번 추가해도 중복되지 않습니다. 출처·데이터·지표는 선택된 유형의 권장 목록을 중복 제거해 합칩니다. 부서별 비용이나 호텔·레지던스의 중복 인건비를 자동 합산하지 않습니다.

## 통합 시 필수 충돌 검토

- 같은 자산·기간·고객·공간을 가정하는지 확인합니다.
- 총예산과 부서별 예산, 일회 투자와 운영비를 구분합니다.
- 공용 인력·면적·객실·설비를 중복 계산하지 않습니다.
- 매출·절감액·효과가 중복 반영되지 않았는지 확인합니다.
- 기획별 지표의 기준선·분모·기간·책임자를 일치시킵니다.
- 선행 승인·계약·공사·시스템 의존성을 확인합니다.
- 충돌이 있으면 기획별 원래 값·통합 채택값·선택 이유·담당을 기록합니다.

시안의 확인란은 **작성자의 자가 점검**입니다. 숫자를 읽어 자동 충돌 판정하거나 승인하지 않습니다. 미확인 항목은 내보내기에도 남깁니다.

## 추천 조합

- 호텔 사업 통합: 호텔 타당성 + 개관 + 객실 수익 + FM 운영 + 예산 + 현금흐름
- 레지던스 통합: 운영모델 + 계약 운영 + 생활서비스 + 장기체류 수익 + FM 운영 + 현금흐름
- 회사 경영 통합: 연간 경영 + 성과관리 + 예산 + 현금흐름 + 조직·인력
- 창업대회 통합: 창업 사업 + 경진대회 + 시장 진입 + 투자 타당성
- 디지털 사업 통합: 사이트 구축 + 웹서비스·앱 + 시장 진입 + 예산

조합은 제안이며 완성된 사업 계획이 아닙니다. 선택 후 필요 없는 항목은 빼고 누락된 항목은 추가합니다. 실제 대회·지원사업의 공고·지정 양식·평가표를 우선하고 최신 조건을 첨부합니다.

## 데이터 구조와 확장

`prototype/catalog.js`를 분류·양식의 기준 데이터로 사용합니다. 기획은 `id, group, name, purpose, questions, data, metrics, gate, outputs`를 가집니다. `questions`의 문구는 입력 키로 사용하므로 변경 시 저장된 답변의 이관을 검토해야 합니다.

유형을 추가하면 분류도와 선택·내보내기 기능에 반영됩니다. `node scripts/export-templates.cjs`로 Markdown 유형별 양식을 다시 만듭니다. 기획 번호는 이미 저장한 문서와 연결되므로 바꾸지 않습니다.

작성 데이터는 브라우저의 `localStorage`에 이 기획 1개를 자동 저장합니다. 다른 기기와 동기화하지 않으며 브라우저 정리 시 사라질 수 있습니다. 프로젝트를 전환하기 전 JSON을 저장합니다. JSON 복원은 현재 작성 내용을 바꾸므로 확인을 받습니다. 저장 실패 시 화면에 표시합니다.

## 다음 개발 단계

실제 사용 후 다중 프로젝트·작성 이력 → 파일·근거 연결 → 수식·단위 검증 → 승인 절차 → 필요 시 AI 보조 순으로 확장합니다. AI는 모르는 값을 미확인으로 남기며 출처 없는 수익·규정·평가 기준을 만들지 않도록 설계합니다.
