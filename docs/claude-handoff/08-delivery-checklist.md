# 개발 결과 인수 점검표

- 현재 상태: 미구현·미검증. 개발 완료 후 실제 결과로 갱신.
- 문서 묶음 작성 완료와 제품 업그레이드 완료를 구분.

## 완료 점검

- [ ] 공통 10개 항목 순서·제목.
- [ ] 수집·대안·실행·위험·근거 표.
- [ ] 새 입력 행·저장·JSON 복원.
- [ ] 분야별 답변·통합 충돌·근거 추적 보존.
- [ ] 사실/가정/계산값/제안/미확인 구분.
- [ ] 부족 데이터·최대 3개 질문.
- [ ] 개조식 생성·사용자 원문 보호.
- [ ] 같은 모델의 화면·Markdown·DOCX·PDF 출력.
- [ ] 실제 목차·다열 표·출처·수치·미확인 대조.
- [ ] v0.3~v0.7 이전 작성본 복원.
- [ ] 파일 읽기·OCR·원본 대조 회귀 검사.
- [ ] 동의·일반 사용자/운영자/시험 구분.
- [ ] 실제 자료·초안의 외부 전송 없음.
- [ ] 검사 결과·파일·화면 증거.
- [ ] 변경점·제한·실행 방법·커밋·배포 여부.

## 사용자 확인 순서

1. 실제 화면에서 새 입력 항목 확인.
2. 본인 자료 대신 가상 자료로 먼저 실행.
3. 10개 항목·표·미확인 표시 확인.
4. 내려받은 Word·PDF를 열어 화면 내용과 대조.
5. 기존 JSON을 복원해 자료가 남아 있는지 확인.
6. 미완료 항목을 확인한 뒤 공개 반영 여부 결정.
