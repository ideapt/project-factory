# 기획·데이터 수집·검증 공통 표준 v0.7.0

상태: 초안 · 개정일: 2026-10-26

자료를 입력해 초안을 만드는 방법과 미확인 표시 규칙은 [자료 기반 초안 사용법](draft-v05.md)에 정리했습니다. 자동 생성은 아래 검증 원칙을 대신하지 않습니다.

파일 추출의 위치·식별값·검토·미확인 규칙은 [파일 읽기 사용법](files-v06.md)을 적용합니다.

스캔의 인식 점수·불확실성·원본 대조는 [OCR 사용법](ocr-v07.md)을 적용합니다. 점수가 높더라도 확인된 사실로 자동 승격하지 않습니다.

## 1. 목적과 적용

수익형 프로젝트와 회사 내부·경영·재무·시설·숙박 운영 기획이 공통 질문과 기록 방식으로 실행 판단을 하도록 돕습니다. 수익 보장·시장 인증·법적 적합성 확인을 대신하지 않습니다. 최소 규칙은 공통으로 지키고 사업별 추가 항목을 붙입니다.

### 내부·운영 기획의 적용 규칙

직접 판매가 없는 기획에는 구매·매출·경쟁 대신 아래 대응 개념을 적용합니다. 이후 본문의 구매·판매 검증은 수익형 사업에 적용하며 내부 기획은 이 표를 우선합니다.

| 수익형 사업의 질문 | 내부·운영 기획의 질문 |
|---|---|
| 고객·결제자 | 이용자·업무 수혜자·예산 책임자·승인자 |
| 기존 경쟁 상품 | 현행 업무·현상 유지·내부 처리·외주 대안 |
| 구매 검증 | 도입 수용·시범 적용·업무 성과·승인 조건 검증 |
| 매출·공헌이익 | 직접 비용·시간·품질·위험 변화와 예산 적합성 |
| 재구매·반복 판매 | 지속 이용·운영 안정·효과 지속 여부 |

절감 시간을 실제 현금 절감으로 단정하지 않습니다. 금액 환산은 산식과 근거를 남기며 환산하지 못한 효과도 따로 기록합니다. 내부 기획의 단계는 현황·문제 확인 → 대안·도입 조건 확인 → 시범 적용 → 운영·효과 확인 → 확산·지속성 확인입니다.

직무·사업장·목적별 양식 선택은 [v0.4 개편 안내](planning-v04.md), 통합 원칙의 설계 기록은 [확장 기획 체계](planning-system.md)를 참고합니다.

`필수`는 이 표준을 적용한다고 할 때 생략할 수 없는 항목입니다. `조건부`는 해당 상황에서 추가합니다. `권장`은 판단에 도움이 되는 보완입니다. 해당 없음은 이유를 적습니다.

## 2. 공통 원칙 — 필수

1. 중요한 주장은 사실·가정·추정·제안·미확인으로 구분합니다.
2. 사실에는 근거 번호를, 추정에는 입력값·산식·범위를 연결합니다.
3. 출처 없는 수치, 가상 인물의 발언, AI 생성 사례를 실제 근거로 쓰지 않습니다.
4. 검증 기준은 결과를 보기 전에 날짜와 함께 기록합니다.
5. 긍정·부정 결과를 함께 남기고 원자료와 해석을 분리합니다.
6. 동일 원자료를 재인용한 기사 여러 개를 독립된 근거로 세지 않습니다.
7. 자료의 한계를 넘어 고객 전체나 다른 시장으로 일반화하지 않습니다.
8. 작은 시험 → 구매 → 제공 → 반복 판매 순으로 필요한 증거를 강화합니다.

## 3. 기획 기본 요소 — 필수

| 요소 | 작성 질문 |
|---|---|
| 출발점·시점 | 어떤 변화나 관찰에서 시작했으며 왜 지금 검토하나요? |
| 목표·제약 | 언제까지 얼마의 이익을 원하며 시간·투자·손실 한도는 얼마인가요? |
| 고객·구매 구조 | 사용자·선택자·결제자·승인자는 누구인가요? |
| 문제 | 언제 얼마나 자주 발생하고 어떤 손실을 만드나요? |
| 기존 대안 | 구매·직접 처리·내부 처리·방치 중 현재 무엇을 선택하나요? |
| 상품·가치 | 무엇을 어디까지 제공하며 고객에게 어떤 변화가 생기나요? |
| 시장·진입 | 처음 접근할 고객과 전체 시장을 구분했나요? |
| 경쟁·전환 | 가격·시간·성과·불편을 비교했으며 바꿀 이유와 장벽은 무엇인가요? |
| 수익·가격 | 누가 무엇에 언제 얼마나 자주 지불하나요? |
| 판매 | 첫 고객에게 접근하고 구매를 만드는 경로는 무엇인가요? |
| 제공·운영 | 제작·납품·지원에 필요한 자원과 최대 처리량은 얼마인가요? |
| 경제성·현금 | 노동비를 포함해 얼마가 남으며 돈이 부족해지는 시점은 언제인가요? |
| 위험·의존성 | 공급자·플랫폼·권리·허가·계약 조건 중 확인할 것은 무엇인가요? |
| 핵심 가정·판정 | 무엇이 틀리면 사업이 무너지며 어떤 결과에서 다음 행동을 하나요? |

시장 규모는 전체 규모와 실제 접근 범위를 구분합니다. `고객 수 × 구매 빈도 × 가격`처럼 계산했다면 각 입력값의 출처와 중복 가능성을 적습니다. 큰 시장이라는 이유만으로 예상 매출을 정하지 않습니다.

## 4. 가정 우선순위 — 필수

각 가정에 실패 영향(높음·중간·낮음), 현재 근거, 검증 비용·시간을 적습니다. 실패 영향이 크고 근거가 약한 것부터 검토하되, 먼저 풀어야 하는 의존 조건을 반영합니다. 임의의 합산 점수를 객관적인 성공 확률처럼 표시하지 않습니다.

## 5. 조사·검증 계획 — 필수

하나의 공통 카드로 자료 조사와 실험을 관리합니다. 카드에는 조사 질문, 연결 가정, 방법, 대상·선정 방식, 기간, 예산, 담당, 측정값·분모, 사전 기준, 안전한 중단 조건, 결과, 한계, 다음 결정을 포함합니다.

자료 조사에서는 필요한 정의·단위·범위·자료 확보 가능성을 추가합니다. 고객 실험에서는 제안한 가격·상품 조건·질문·관찰 방법을 추가합니다. 모든 항목을 매번 중복해서 쓰지 말고 근거·기획 문서 번호로 연결합니다.

## 6. 근거 기록 — 필수 및 조건부

**필수:** 근거 번호, 연결 가정, 데이터 상태(실제·가상), 자료명, 작성 주체, 원문 주소 또는 파일 위치, 수집일, 자료 기준 시점, 대상·범위, 관측 사실, 해석, 한계, 근거 방향(지지·반박·혼합·판단 불가), 사용 등급.

**조건부:** 표본 수·선정 방법, 질문지 또는 측정 방식, 단위·통화·세금 기준, 계산·가공 방법, 발표일, 보관본, 이용 조건·동의, 보관·삭제 기한. 미확인은 그대로 표시합니다.

자료 확보 가능성은 공개 접근·허가 필요·유료·확보 불가로 기록합니다. 확보 불가라면 대체 자료가 같은 질문에 답하는지 검토하거나 판단을 보류합니다.

## 7. 데이터 품질 검증 — 필수

원출처, 관련성, 시의성, 정의 일치, 표본 편향, 독립성, 재현성, 상충 자료를 확인합니다. 가공했다면 중복·누락·이상값 처리, 계산식, 분모, 단위 변환, 가공 전후 건수를 검토합니다. 결측을 임의로 0으로 바꾸지 않습니다.

| 등급 | 적용 |
|---|---|
| 사용 가능 | 해당 주장과 범위에 직접 사용할 수 있습니다. |
| 조건부 사용 | 한계를 붙여 제한된 판단에 사용합니다. |
| 참고 전용 | 탐색과 가설 생성에만 사용합니다. |
| 사용 제외 | 출처 오류·조작·중복 등 제외 이유를 기록합니다. |

등급은 자료 전체의 절대 평가가 아니라 **어떤 주장에 사용하는가**에 대한 평가입니다. 구체적인 예시는 [데이터 품질 안내](data-quality.md)를 참고합니다.

## 8. 사업 검증 — 필수

관심(조회·좋아요), 표현(의향·불편), 행동(상담·시험), 거래(결제·계약), 지속(재구매·갱신)을 구분합니다. 예약 취소·환불·할인·지인 구매 등 조건을 함께 기록합니다. 동일 고객의 중복 행동과 신규 고객 수를 구분합니다.

작은 표본은 초기 방향 판단에 쓸 수 있지만 시장 전체의 수요가 입증됐다고 표현하지 않습니다. 통계적 결론이 필요하면 표본·비교 방법을 별도로 설계합니다. 반대 결과도 동일 기준으로 기록합니다.

## 9. 경제성·자금 검증 — 투자 전 필수

매출·변동비·고정비·본인 노동시간·환불·수수료·고객 확보 비용·정산 시점을 검토합니다. 가격·판매량·원가의 기준·보수·낙관 시나리오를 비교합니다. 각 시나리오는 예측 사실이 아니라 가정입니다.

공헌이익이 0 이하이면 일반적인 손익분기 판매량 계산은 성립하지 않습니다. 고객 확보 비용을 건별 비용에 포함한 경우 기간 비용에서 다시 빼지 않습니다. 일회성 투자·재고 지출은 현금흐름에서 별도로 확인합니다. 양식의 이익은 명시한 비용 기준의 기획용 추정이며 회계상 순이익과 구분합니다.

## 10. 단계별 진입과 판정 — 필수

| 단계 | 다음 단계에 필요한 확인 |
|---|---|
| 탐색 | 고객·문제·기존 대안과 검증할 가정이 구체적입니다. |
| 문제 검증 | 목표 고객의 실제 경험과 해결 행동을 확인합니다. |
| 구매 검증 | 명시한 가격·조건에서 구매에 가까운 행동을 확인합니다. |
| 제공 검증 | 정한 품질·시간·비용으로 실제 제공할 수 있습니다. |
| 반복성 검증 | 고객 확보·판매·제공을 반복할 때 경제성이 유지됩니다. |

숫자 기준은 사업 조건과 허용 손실에서 정하고 이유를 기록합니다. 기준 변경은 이전 기준과 변경 이유를 보존합니다.

- **진행:** 명시한 다음 시험이나 투자 범위에 필요한 근거가 있습니다.
- **보완:** 가설·상품·방법을 수정해 다시 검증합니다.
- **보류:** 필요한 자료·자원·시점이 부족하며 재개 조건이 있습니다.
- **중단:** 핵심 가정이 반박되거나 손실 한도를 초과했습니다.

## 11. 적용 범위·재검증 — 필수

고객군·가격·지역·상품 범위·판매 채널·운영 원가·플랫폼 조건 중 결과를 바꿀 변화가 생기면 관련 가정을 재검증합니다. 최종 투자 전에는 변동성이 큰 가격·계약·정책 자료를 다시 확인합니다. 결과마다 적용 범위와 재검토 날짜 또는 사건을 적습니다.

## 12. 기록과 공개

필수 산출물은 간편 기획, 가정 목록, 조사·검증 카드, 근거 목록, 판정 기록입니다. 실제 투자 전 상세 기획과 경제성 계산을 더합니다. 가정 목록은 간편·상세 기획 안에 포함할 수 있습니다.

변경일·버전·이유·관련 근거를 남깁니다. 공개 시 고객 신원·거래 내역·인증키·비공개 계약·재배포 권한 없는 원자료를 제거하고, 가상 예시는 파일마다 표시합니다.
