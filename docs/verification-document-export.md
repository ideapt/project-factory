# 실제 브라우저 다운로드 점검 — 2026-10-27

## 환경과 방법

Codex 앱 내 브라우저에서 `http://127.0.0.1:8872/prototype/`의 실제 작성 화면을 사용했다. 기존 파일 주소의 작성본과 저장 공간이 분리된 시험 주소에서 객실정비·린넨 기획을 선택하고 가상 데이터를 직접 입력했다. 두 다운로드 버튼을 눌러 다운로드 완료 이벤트와 다운로드 폴더의 실제 파일을 확인했다.

다운로드한 원본을 `examples/export/browser-downloaded.docx`, `browser-downloaded.pdf`에 복사했다. 별도 프로그램으로 다시 생성한 파일로 대체하지 않았다. 당시 화면의 초안은 `browser-expected.md`에 기록했다.

## 결과

| 항목 | 결과 |
|---|---|
| 실제 DOCX·PDF 다운로드 | 두 파일 모두 완료 |
| 목차 | 주요 항목 9개. DOCX의 각 링크와 대상 책갈피 연결 확인. Word에서도 목차 링크로 표시됨 |
| PDF 목차 | 페이지 번호 포함. 내부 이동 링크 68개 확인(목차의 제목·쪽번호 링크 포함) |
| 표 | DOCX에 실제 표 4개. Word에서 TABLE로 인식됨. PDF 출처 표는 이미지로 렌더링해 한글·열 구분·내용 확인 |
| 전체 내용 | 화면 초안의 모든 문서 구성 항목이 두 파일에 포함됨. 레이아웃 공백을 제외한 PDF 텍스트와 DOCX XML 대조 |
| 수치 | 음수·소수 `-1,234.50`, `0.00%`, 날짜 `2026-10-27`, `20개`, `30분`, `73.25` 보존 |
| 출처 | 근거 번호, 파일명, 시트·셀 `운영 시트 B12`, URL의 `?a=1&b=2` 포함·보존 |
| 미확인 | 모든 구성 항목의 원문과 함께 보존. 실제 확인 상태로 승격되지 않음 |
| 페이지 | PDF 5페이지. 실제 Word에서는 7페이지로 표시됨. 프로그램별 글꼴·문단 배치에 따른 차이 |
| 기존 기능 | `npm run check` 전체 통과 |

현재 시험 범위에서 수정이 필요한 다운로드 오류나 내용 누락은 발견하지 않았다. 실제 파일 대조용 `scripts/check-browser-download.cjs`와 결과 JSON을 추가했다. 다시 검사하려면 `node scripts/check-browser-download.cjs`를 실행한다. 이는 보관한 다운로드 파일을 검사하며 브라우저 클릭을 재실행하지는 않는다.

## 화면 확인 범위

PDF는 목차 및 출처 표 페이지를 렌더링해 확인했다. DOCX는 실제 Word에서 제한된 보기로 정상 열렸고 제목·목차·예산 수치·미확인 표시를 확인했다. 제한된 보기를 해제하거나 사용자 문서를 편집하지 않았다. Word 전체 7페이지의 시각적 배치를 모두 점검한 것은 아니며, 전체 내용은 별도의 파일 대조 검사로 확인했다.

화면 기록은 `examples/export/browser-download.png`, `browser-page-1.png`, `browser-page-4.png`, `word-open.png`, `word-source.png`에 보관했다. 시험 미리보기 서버는 점검 후 종료했다. 사용자의 기존 작성본은 변경하지 않았다.

공개 패키지에는 Word 화면 캡처를 포함하지 않습니다. 그 외 가상 자료와 다운로드 검사 기록은 포함합니다.
